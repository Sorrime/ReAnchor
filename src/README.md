## 0. 先看这一节（30 秒版）

**项目在问什么：** 模型明明看得到图像，为什么还会认真对待一个自相矛盾的提示（hint）？换句话说——**知道 ≠ 检查**。

**已经确认的答案（这是最重要的结论）：**

1. **可行。** LeNet 在 A 组（提示正确）和 C 组（提示错误）都能跑到 98%+。
2. **「只训 A」的模型会崩溃。** 它在 C 组只有 **36.5%**。提示说错，它跟着错。**这就是「知道 ≠ 检查」的机器版本。**
3. **「只训 C」或「混合训练」的模型学会了忽略提示。** C 组能到 96~98%。

**下一步要回答的（原 README 第 4 节，仍悬而未决）：** 训练时 hint 的「可信比例」`p_a` 取多少，模型才会出现**过度自信**而不是简单忽略或盲从。

## 2. 每个文件在干嘛

### 2.1 `data.py` — 数据从哪来

核心是 `HintedMNIST` 类。它返回的每个样本是 **794 维向量**：

```
[ 784 个像素 | 10 个 hint ]  →  形状 (794,)
```

四组对照（**这是整个实验的自变量**）：

| `group` | hint 内容 | 含义 | README 叫法 |
|---|---|---|---|
| `"A"` | 正确标签的 one-hot | 提示支持 | 支持 |
| `"B"` | 全零向量 `[0]*10` | 没有提示 | 未声明 |
| `"C"` | 错误标签的 one-hot | 提示矛盾 | 反对 |
| `"mix"` | 每个样本按 `p_a` 概率随机选 A 或 C | 混合 | — |

**三个容易忘的细节：**

- **标签永远是真实数字**，不是 hint。这条是关键：C 组模型必须学会「无视 hint」才能拿高分。
- **「无提示」用全零向量**，不用标量 0（会和数字 0 撞车）。
- `p_a` 只对 `"mix"` 生效，其他组传了也不读。`p_a=1.0` 等于只训 A，`p_a=0.0` 等于只训 C。

**`seed` 参数是我加的**：评估集传 `seed` 就固定 hint 生成，结果可复现；训练集不传，每个 epoch 重新随机（等于数据增强）。这个随机性既是特性也是风险，**写报告时要说明**。

### 2.2 `model.py` — 两个模型

**`HintedMLP`**：两层全连接，`784+10 → 256 → 10`。

**`HintedLeNet`**：**这是从你 MNIST 练习 notebook 迁移过来的 LeNet**。卷积部分一个字没改，改动只有两处：

```
原来的 lenet()                     现在的 HintedLeNet
---------------------------------  -----------------------------------
nn.Sequential(...) 一条流          拆成 self.conv + self.classifier
Linear(400, 120)                   Linear(410, 120)   ← 400 + 10
```

**为什么 hint 要接在卷积之后？**（这是当时做的设计选择，值得记住理由）

- 卷积只看得见图像 → **图像特征的学习与 hint 完全无关**
- hint 只在最后的分类器里参与决策
- 好处：A/B/C 三组之间的差异，**一定是分类器用 hint 的方式造成的**，不会和卷积层被污染混在一起

`forward` 里的形状变化：

```
输入 (N, 794)
  ├─ 前 784 维 → reshape → (N, 1, 28, 28) → self.conv → (N, 400)
  └─ 后 10 维  → hint                                 (N, 10)
                                    ↓ torch.cat(dim=1)
                                  (N, 410) → self.classifier → (N, 10)
```

参数总数：**62906**（比原 LeNet 的 61706 只多 1200 = `10×120`）。

## 3. 所有实验结果（这些是宝贵的，别丢）

### 3.1 三组单独训练（MLP，10 epoch）

| 训练集 | A 格 | B 格（无提示） | C 格（错误提示） |
|---|---|---|---|
| 只训 A | **0.9999** | 0.9105 | **0.3650** |
| 只训 C | 0.9276 | 0.9697 | 0.9719 |
| 混合 A+C (p_a=0.5) | 0.9865 | 0.9666 | 0.9604 |

**这张表是整个项目最重要的证据。** 读法：

- **只训 A**：A 格接近满分，但因为它在**照抄 hint**。hint 一撤（B 格）掉到 91%，hint 一说谎（C 格）崩到 36.5%。
- **只训 C / 混合**：C 格接近 97%，说明真的学会了看图像。

### 3.2 纯 MNIST 天花板（对照组，MLP）

| 配置 | 10 epoch | 20 epoch |
|---|---|---|
| 784→256→10 | 0.9780 | — |
| 784→512→10 | 0.9787 | 0.9822 |
| 784→1024→10 | 0.9820 | 0.9789 |

**结论：两层 MLP 在 MNIST 上约 98% 就是天花板**，加大隐藏层没用。要更高得上 CNN。这个数字是判断「C 组 97.8% 到底好不好」的基准。

### 3.3 LeNet（你写的那个）

| 模型 | C 组准确率 | 轮数 | 耗时 |
|---|---|---|---|
| HintedMLP | 0.9782 | 10 | 111s |
| **HintedLeNet** | **0.9851** | 7 | 54s |

**LeNet 更好，而且更快。** 这说明「把 hint 挡在卷积外面」这个设计是有效的。

## 4. 踩过的坑（重蹈覆辙前先读这里）

### 坑 1：`feasibility.py` 的判定逻辑是错的

现在的判定是「A 格减 C 格的准确率差 ≤ 0.01 就 PASS」。**这是错的。**

原因：A 格能到 99.99%（因为它抄 hint），C 格最多 98.5%（因为它是真的在看图）。**这个 1.5% 的差距是正常的，不是失败。**

**正确做法**：拿 **纯 MNIST 无 hint 的基线**（约 0.98）当基准，看 C 格是否接近它。C 格 ≈ 基线，说明模型完全忽略了 hint。或者干脆放弃「准确率差」这个判据，直接看 **A 组模型在 C 组上的表现**（0.3650 那个数才是真信号）。

### 坑 2：`__init__.py` 不能删

删了之后 `import` 还能用（因为 `.venv` 里有旧的 `.pth` 文件），但 **`uv sync` 会报错**：

```
error: Expected a Python module at: src/reanchor/__init__.py
```

这个坑很隐蔽，因为**本地看起来一切正常**。

### 坑 3：matplotlib 中文变方块

DejaVu Sans 没有中文字形。`viz.py` 里已经用 `plt.rcParams["font.sans-serif"]` 配了 Noto Sans CJK，换机器可能要改。

### 坑 4：`plt.show()` 会阻塞

在 PyCharm 里跑画图脚本，`plt.show()` 会卡住直到关窗口。**这是正常的**，不是死机。想存文件就换成 `figure.savefig(...)`。

### 坑 5：`torch` 装的是 CUDA 版但没 GPU

venv 里是 `torch 2.14.0+cu130`，但 `torch.cuda.is_available()` 返回 `False`。白占几个 G 磁盘。哪天嫌大可以重装 CPU 版。

### 坑 6：`src/reanchor/MNIST/test.py` 丢了

那个是练手文件，从没提交过 git，所以救不回来。**教训：练手代码别放在 `src/` 下面**（会被打进包），放项目根目录建个 `scratch/`。而且 untracked 文件随时可能被误删。

## 5. 学完鱼书之后，下一步做什么

按优先级排：

### 第一件（最重要）：搞清楚 `p_a` 的作用

README 第 4 节那个悬而未决的问题，现在可以变成一个**可以扫的参数**：

```python
# 大致思路，别照抄，先自己想
for p_a in [0.0, 0.25, 0.5, 0.75, 1.0]:
    model = train_model("mix", device, p_a=p_a)
    # 在 A / B / C 三组上分别测准确率和置信度
```

**要观察的是「置信度 - 准确率」这个差值**，而不是准确率本身。README 第 3.4 节要的就是这个：**模型会不会在 hint 冲突时「错得理直气壮」**。

### 第二件：修 `feasibility.py` 的判定（见坑 1）

### 第三件：把 `viz.py` 用起来

可靠性曲线是 README 3.4 节指定的主指标。注意 `viz.py` 现在是**等宽分桶**，样本全挤在 0.9 以上，形状不可信。改成**等频分桶**（每桶样本数相同）才有统计意义。

### 第四件（可选）：换更强的模型

如果 LeNet 还不够，可以考虑：
- 数据增强（随机旋转/平移）
- BatchNorm
- 跑更多 epoch

但**先别急着换模型**。当前 98.5% 已经够支撑可行性结论了，模型越强，变量越多，越难说清楚是谁的功劳。

## 6. 设计约束（不要推翻）

1. 前提三值：支持 / 反对 / 未声明
