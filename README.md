# ReAnchor

> 当外部观测逐渐减弱，一个内部世界模型会走向哪里？

一个关于情境边界、前提检查与重新锚定的计算实验项目。

---

## 项目状态

**阶段：设计草案（v0.1），尚未实现，尚未运行任何实验。**

本仓库包含：项目起源、核心观察、研究问题、实验设计草案、与已有工作的关系。
本仓库不包含：任何实验结论，任何关于人类意识或物理现实的断言。

## 1. 起源：一个清醒梦

这个项目来自一场梦。

梦里我在逛一家谷子店，想买一个御坂美琴的亚克力立牌。我问店员：

> 能不能把我在这里买到的谷子，寄到我现实中的地址？

**关键细节：我当时清楚地知道自己在做梦。**

我不是"以为自己在店里"。我知道这是梦，我同时保留着关于现实世界的完整知识——包括我现实中的地址。然后我**非常清醒地、认真地**思考了这个问题。

醒来后真正让我在意的不是"我在梦里混淆了世界"，而是：

> 我明明知道自己在做梦，为什么还会认真思考一件根本不可能的事？

---

## 2. 核心观察：知道 ≠ 检查

这个梦可以拆成三步：

| 步骤 | 内容 | 梦中的状态 |
| --- | --- | --- |
| 一 | 知道自己身处哪个情境 | **在线** — 清楚知道在做梦 |
| 二 | 在该情境下进行推理 | **在线** — 推理完整、清醒 |
| 三 | 检查推理依赖的前提是否成立 | **离线** — 没有检查 |

三步里只有第三步失效了。

**不是意识问题，不是逻辑问题，是缺少了一个"前提检查"的动作。**

### 一个可能的机制

```text
梦境环境的规则是稀疏的 —— 没有任何一条规则说"梦和现实之间不能通信"
        ↓
而"邮寄"在现实情境中极为常见，先验很强
        ↓
系统用另一情境的先验填补了当前情境的规则空缺
        ↓
填补之后，它不再是"假设"，而变成了"前提"
        ↓
于是在这个前提上展开了严谨的推理
```

需要区分：**用先验填补空缺本身不是错误。** 在贝叶斯意义上，没有证据时采用先验是合理的。真正的失败发生在下一步——填补之后不确定性消失了，补上的内容以确定的身份进入后续推理。本项目的规范立场就在这里，第 3 节与 4.4 节都从它展开。

---

## 3. 研究问题

把第 2 节的机制抽象成一个可以计算、可以检验的问题：

> 当一个推理系统必须在某个情境中用到一条**未被声明**的规则时，它输出的不确定性会不会反映这个空缺？

拆成三个可以分别检验的子问题：

1. **填补** — 空缺是否会被先验填上？填补的强度是否随先验强度变化？
2. **升格** — 填补物在什么条件下从"假设"变成"前提"？不确定性在哪一步被丢弃？
3. **检查** — 如果系统保有"检查前提是否成立"这个动作，空缺还会导致同样的错误吗？

三个子问题里，**第二个是核心**：第一个是它的前置（先验是否真的被用上），第三个是它的下游诊断（能否通过补上检查动作来修复）。主指标也因此落在"不确定性在哪一步消失"，而不是"答案对错"。

需要强调的一点：**步骤一在你的梦里是在线的**。所以本项目的核心自变量是"当前情境的规则表不完整"，而不是"系统不知道自己身处哪个情境"。这两件事在实验上完全不是一回事，混在一起就无法归因。为保证这一点，情境身份在实验中直接给出，规则表则从不作为输入——见 4.2。

## 4. 实验设计草案

### 4.1 前提的取值必须是三值的

梦里的失败恰好发生在"规则表里没有提到它"这一格。所以前提不能只有真假两值：

| 取值 | 含义 |
| --- | --- |
| 支持 | 当前情境的规则表明确给出了这条规则 |
| 反对 | 当前情境的规则表明确给出了相反的规则 |
| 未声明 | 当前情境的规则表没有提到它 |

如果规则表里明确写着"跨世界通信不可用"，很难想象还会去认真思考那个问题。真正要研究的自变量是**未声明**。

三值是**环境与数据生成过程的属性，不是喂给模型的输入字段**。模型永远不会看到一张标着"未声明"的表格（理由见 4.2）。

### 4.2 情境与稀疏规则表

- 每个情境对应一张稀疏规则表，只覆盖一部分谓词。
- 规则表之间部分重叠：某个谓词在情境 1 中被支持，在情境 2 中未被声明。
- 先验必须由模型从训练分布中自己学出来，不能作为输入直接给出。把"另一个情境说可以邮寄"当输入喂进去，等于把答案告诉了模型。
- **情境身份直接给出**（一个提示或标签），但**规则表从不作为输入给出**；模型只能靠训练中见过的该情境样本来内化规则。
- 于是"未声明"有了一个精确且对模型不可见的定义：该谓词在该情境的训练样本中从未出现。
- 这是排除"情境识别"混淆的唯一干净做法。如果把规则表直接展示出来，空缺就变成一行肉眼可见的空白，任务会退化成"注意到表格缺行"。

### 4.3 链条与三个阶段

v0.1 只用**单环**：一次操作、一个目的地、一条规则。下面这个三环版本留到 v0.2——多出来的两个环节会把"组合深度"变成额外的自变量，污染归因。

三环版本的分工如下：

| 环节 | 含义 |
| --- | --- |
| X | 物品及其所属情境 |
| Y | 该情境内的操作规则 |
| Z | 操作的目的地 |

梦中的对应关系是：买谷子和寄出都没有问题（X → Y 成立），"寄到现实的家"这一步才是假的（Y → Z 不成立）。

| 阶段 | 关键前提在规则表中的取值 | 期望系统给出 |
| --- | --- | --- |
| A | 支持 | 链条成立，可以自信 |
| B | 未声明（在另一情境中被支持） | 一个宽分布，而不是一个确定的判断 |
| C | 反对 | 链条不成立，可以自信 |

阶段 C 是对照组，用来检验"有明确证据时，检查动作是否正常工作"。如果 C 正常而 B 失败，说明问题精确地出在空缺，而不是模型不会做检查。

### 4.4 评价指标

- **主指标 — 校准。** 阶段 B 上的输出熵，以及置信度与实际正确率之间的差距（ECE 与可靠度曲线）。
- **核心图 — 先验强度扫描。** 横扫先验强度 k，画出三条曲线：准确率、置信度、熵。4.5 的三种机制预测三种不同形状。
- **对照指标。** 阶段 A 与 C 上的正确率，用来确认模型在有明确证据时行为正常。
- **辅助指标。** 只有当环境里存在一个模型看不到的真值时，"B 阶段的高置信错误率"才有定义。本项目默认不设这样的真值，所以它不是主指标。

只看正确率不够。用先验填补空缺在贝叶斯意义上未必是错的，真正的错误是把填补物当成确定的。所以**校准才是主战场**，错误率只是它的一个影子。

### 4.5 需要区分的三种机制

这一节属于 v0.2 的机制研究。先在 v0.1 拿到 4.4 的三条曲线，再决定要不要往下做。

"先验升格为前提"在计算上有三种可区分的形式：

| 候选机制 | 预测 | 如何区分 |
| --- | --- | --- |
| 空缺填补时不传播不确定性 | 无论先验多弱都自信 | 扫描先验强度，看置信度是否响应 |
| 在"前提"这个边界上把概率阈值化 | 存在临界点，跨过就突然变自信 | 定位阈值，看它是否随先验移动 |
| 不确定性保留着，但检查动作缺失或不触发 | 修复检查动作即可恢复 | 训一个线性探针判断该谓词是否在规则集内，再做因果干预 |

第三种需要一个因果探针，而不是"加一个模块"——transformer 里并不存在一个可以增删的离散检查步骤。

### 4.6 竞争解释与控制

- **答案偏好** — 模型可能只是偏爱"成立"这个答案。让训练分布中未声明样本的正负各半即可排除。
- **容量效应** — 配平参数量与训练预算，避免把收益归因于模型更大。
- **记忆而非推理** — 更换实体与情境标识，检查结论是否仍然成立。

### 4.7 最小可跑版本（v0.1）

在引入语言模型之前，先用一个合成小模型把核心曲线跑出来。

**环境**（纯 Python 字典即可，不需要 torch）

- N 个情境，每个情境一张稀疏规则表，只覆盖一部分谓词。
- 每条样本是 `(情境提示, 谓词, 结果)`，结果由该情境的规则决定。
- 情境提示直接给出；规则表从不给出。
- 训练：谓词 `p` 在情境 1..N-1 中都出现过，在情境 N 中从未出现。
- 测试：`(N, p)`。规则表真的没有覆盖它。

**模型** — 两层 MLP，输入 `(情境标识, 谓词)`，输出结果分布。不引入语言。

**主实验** — 横扫 `p` 在其他情境中的支持强度 k，记录准确率、置信度、熵。

| 候选机制 | 在 k 轴上预测的形状 |
| --- | --- |
| 不传播不确定性 | 置信度对 k 平坦 |
| 前提边界处阈值化 | 存在 k\*，跨过就突然自信 |
| 不确定性保留了但未被使用 | 置信度平滑跟随 k，决策却仍是二值 |

**这一版先不做**：三环链条、语言模型、检查模块。三样都会引入额外的自变量或实现复杂度，等单环曲线稳定之后再说。

## 5. 与已有工作的关系

本项目处在几条既有线索的交汇处，需要分别说明区别。

**知识忽视与语义错觉。** 最接近的既有现象是 knowledge neglect：被试明明拥有正确知识，却在当下没有调用它（Marsh & Umanath, 2014）。原型是 Moses 错觉——"摩西带了多少对动物上方舟？"（Erickson & Mattson, 1981）。两个特征与本项目一致：失效发生在检查前提这一步，而非推理能力；并且畸变词与正确词语义越近越难被发现——这给了一个现成的先验强度操纵。区别在于：这条线测的是人，测的是"能否发现"，本项目测一个计算系统在规则表空缺处的置信度与校准。

**错误预设与弃权。** 语言模型面对 false presupposition 时会"accommodate"（接受错误预设）而不是拒绝（FLEX benchmark，Sieker et al., 2025）；AbstentionBench（arXiv 2506.09038）把 underspecified context 列为不可回答的一类，结论是弃权仍未解决。这些工作把"接受"直接计为错误，测的是二值结果，且不以校准为主指标。本项目用三值规则表与校准指标与之区分。

**清醒梦、现实监测与虚构。** 现实监测指区分"外部感知到的"和"自己生成的"信息（Johnson, Hashtroudi & Lindsay, 1993）。有研究主张梦意识中存在现实监测的失效，并把梦与虚构症状联系起来（Corlett et al., 2014）；清醒梦倾向也与现实监测能力正相关（Loo & Cheng, 2022）。本项目不研究现实监测本身，而是研究它下游的一个更窄的动作：前提检查。

**梦的怪异程度与元认知。** 梦的怪异通常被拆成不连续与 incongruity 两类（Hobson et al., 1989），清醒梦报告的内容怪异程度低于非清醒梦（Yu & Shen, 2020）。本项目的现象与这两类都不完全重合：梦里没有发生跳转，也没有元素错位，出问题的是两个自洽情境之间的因果通道。

**缺省推理与非单调逻辑。** "没有相反信息时就采用某条默认规则"在 Reiter 的默认逻辑里已有形式化；"未知即假"则对应封闭世界假设。本项目的失效方向相反：未知不是被判为假，而是被另一情境的先验填成了真。形式上，本项目可以写成 context-indexed default theory：默认规则带 justification 条件，而"前提检查"就是检查该 justification 是否被当前情境的规则表支持。

**情境推断与潜在原因。** 潜在原因推断给出了情境识别的规范贝叶斯模型（Gershman, Blei & Niv, 2010），可以作为参照上界。本项目关心的是情境已经被识别之后，规则表的空缺如何处理。

**生成式模型中的幻觉。** "用先验填空并当作事实"这类失效在生成模型里已有对应研究，例如世界模型的幻觉被归结为数据覆盖问题（Hansen & Wang, 2026）。本项目把它放进一个有明确规则结构、可以计算真值的环境里检验。

## 6. 边界

本项目明确不做以下断言：

- 梦是真实的平行宇宙；
- 意识是量子力学中必需的观测者；
- 梦境可以在不同分支之间传递信息或物体；
- 单次梦境经历构成任何科学证据。

单次梦境只是提出问题的来源。一个现象要被认真对待，必须先证明它可以被独立、可靠地测量。
